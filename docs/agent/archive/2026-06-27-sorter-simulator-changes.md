# Python Simulator Changes

Last updated: 2026-06-27, Asia/Shanghai.

This document records Python simulator changes made while fixing the GUI/TCP package movement issue and making future agent debugging more reliable.

## Protocol Model

- The simulator must not send package IDs to the board in sensor messages.
- `SENSOR,id=2,state=<0|1>` and `SENSOR,id=4,state=<0|1>` model real hardware sensors.
- Package IDs in simulator logs are local debugging metadata, not protocol truth.
- Board `PKG,id=...` lines are diagnostic state references. They must not be the only reason a local package teleports between belts.
- Sensor information has priority. If sensor release or completion is missing and timeout expires, the simulator safely advances and logs `TIMEOUT_SAFE_ADVANCE`.

## Observability Changes

### Raw TCP Packet Logging

File:

- `esp32_sorter_sim_py/transport.py`

Change:

- Every board TCP SIM packet is logged as:

```text
RX_PACKET_RAW seq=<n> bytes=<payload_len> lines=<parsed_lines> preview=<payload_preview>
```

Reason:

- This makes it possible to prove whether a missing `MOTOR` or `STATUS` line was:
  - never generated by the board,
  - lost in TCP,
  - dropped by Python packet parsing,
  - or parsed but mishandled by simulator logic.

### Log Audit Coverage

File:

- `esp32_sorter_sim_py/log_audit.py`

Changes:

- Counts `transport_packets`.
- Fails on `RX_PACKET_GAP`.
- Fails on `RX_PARSE_DROP`.
- Fails on `RESULT fail`.
- Fails on `BOARD_MOTOR_MISMATCH`.
- Tracks latest received motor state so board B-state can be checked against M2.
- Keeps previous checks for `FAULT`, `DESYNC`, `POSE_ASSERT`, unexpected `DROP`, transfer order errors, and C direction mismatch.

Important audit rule:

- Terminal stdout is not reliable proof of correctness.
- The run log and `log_audit` result are the source of truth.

## UI And Simulator Behavior Changes

### Startup Synchronization

File:

- `esp32_sorter_sim_py/ui.py`

Changes:

- On TCP connection, the UI resets local simulation state and sends board `RESET`.
- It then sends config and waits for board `STATUS ... reason=config`.
- UI auto-test batch starts only after config acknowledgement.
- Pre-ready motor lines are buffered and replayed after config sync.
- If the UI test exits while packages are still active, it writes `RESULT fail ... reason=UI_TEST_INCOMPLETE`.

Reason:

- Prevent stale board state or stale motor commands from being treated as current UI state.

### UI Display Audit

File:

- `esp32_sorter_sim_py/ui.py`

Changes:

- `POSES` records logical package positions and motor states.
- `UI_RENDER` records canvas coordinates and displayed belt motion text.
- B-belt direction display uses M2 direction.
- The S2 pose assertion now allows the valid protocol ordering where M1 forward arrives briefly before `STATUS reason=a_to_b`.

Reason:

- Agents can compare local physics and actual UI display without relying on screenshots alone.
- Valid board command ordering should not be reported as a false UI failure.

### Physical Movement Model

Files:

- `esp32_sorter_sim_py/simulation.py`
- `esp32_sorter_sim_py/tests/test_simulation.py`

Key behavior:

- Packages move only with the owning belt motor.
- A package remains on A until the A-to-B physical edge and valid acknowledgement.
- A package remains on B until the B-to-C physical edge and valid acknowledgement.
- C-belt movement follows M3 direction; if M3 direction contradicts package class target, the simulator logs `C_DIRECTION_MISMATCH` instead of hiding the board error.
- Timeout fallback is safe advance, not drop, when sensor information is missing.

## Agent Debugging Rule

For future movement issues:

1. Check the newest log first.
2. Run `python -m esp32_sorter_sim_py.log_audit --latest`.
3. Compare `RX_PACKET_RAW`, `RX`, `POSES`, and `UI_RENDER`.
4. Do not claim success from stdout or a serial headless run alone.
5. If the user saw the problem in the GUI, reproduce with Tk GUI + TCP, not only unit tests.
